# 엘리베이터 배차 시뮬레이션 - 기본판

- 2026년 2학기 대학글쓰기2(과기글)에서 진행된 주제탐구에 사용한 코드 및 실험 결과를 정리한 Repository이다.

최신 가설·실험 방법·결과·판정은 [연구 현황](RESEARCH_STATUS.md)에, 분석마다의 변경 이력은 [분석일지](ANALYSIS_LOG.md)에 정리한다. 아래의 초기 결과와 후속 실험 기록은 당시의 단계 구분을 유지한다.

주제탐구 계획서의 핵심 비교를 먼저 실행해 볼 수 있도록 만든, 외부 패키지가 필요 없는 Python 시뮬레이터다. 아직 실제 건물의 정밀한 디지털 트윈은 아니며, **배차 규칙과 평가 지표를 검토하기 위한 최소 모델**이다.

현재 주연구 질문은 **“오래된 호출 우선의 개선은 재배분 자체와 호출 순서 중 무엇에서 오는가?”**로 구체화했다. 아래의 기존 세 방식 실험은 예비실험이며, `ablation_experiment.py`가 기능을 분리한 본 실험이다.

## 승하차 시각화 실행

Python 3.10 이상에서 외부 패키지 설치 없이 실행한다.

```powershell
python visualize_elevator.py --open
```

기본값은 혼잡 퇴근형에서 5분간 승객을 발생시킨 뒤 모두 도착할 때까지 계산하고, B 무작위 호출 순서와 C 오래된 호출 순서를 나란히 보여 준다. `output/visualization/elevator_replay.html`에 모든 자료를 넣어 저장하므로, 다음부터는 이 HTML을 브라우저에서 직접 열면 된다. 인터넷이나 별도 서버가 필요 없다. 원자료 JSON과 예시 실행 조건 `.protocol.json`도 함께 저장한다. 이 짧은 예시의 결과를 본 실험의 결론으로 사용하지 않는다.

화면에서 차량 이동·차내 승객·층별 상하행 대기열·최장 대기와 승하차를 볼 수 있다. 재생·일시정지, 배속, 시간 이동, 차량 내 승객 클릭, 현재 장면 SVG 저장을 지원한다. SVG는 PowerPoint에서 크기를 키워도 선명하게 사용할 수 있다. 화면의 인원수는 1초 간격 계산 상태이며, 승하차 시점의 원 이동은 설명용 강조다. 정차 순간에 승하차를 반영하는 기존 모형은 유지한다.

```powershell
# 본 실험과 같은 30분 발생 구간으로 직접 계산
python visualize_elevator.py --duration 1800 --seed 202411191 --order-seed 6619 --output output/visualization/long_replay.html --open

# 작은 건물로 동작 이해
python visualize_elevator.py --floors 8 --elevators 2 --capacity 6 --duration 180 --pattern up_peak --output output/visualization/small_replay.html --open

# A 기본 ETA도 함께 표시
python visualize_elevator.py --strategies eta redispatch_eta age_order_eta --output output/visualization/three_policies.html
```

현재 연구 자료의 [대표 재생](output/trace_analysis/representative_replay.html)도 미리 만들어 두었다. 중앙값 기준으로 고른 승객 씨앗 202411191이며, B는 순서 씨앗 6619 한 개의 실제 경로다. 본 실험에서 B를 순서 5개 평균으로 분석한 것과 구분한다. 포스터에 쓸 수 있는 [승하차 장면 SVG](output/trace_analysis/boarding_scene.svg)·[PNG](output/trace_analysis/boarding_scene.png), [대기 구간 분해 SVG](output/trace_analysis/response_decomposition.svg)·[PNG](output/trace_analysis/response_decomposition.png)도 저장했다.

## 현재 구현 범위

- 25층, 엘리베이터 3대, 정원 12명
- 승객은 포아송 과정으로 도착하며 출발층과 목적층은 교통 패턴에 따라 정함
- 계획서의 세 교통 패턴을 기본 비교함
  - **up_peak(출근형)**: 기본값으로 85%가 1층에서 상층으로 이동
  - **interfloor(층간 이동형)**: 2~25층 사이에서 이동
  - **down_peak(퇴근형)**: 기본값으로 85%가 상층에서 1층으로 이동
- 기존의 **uniform(균일 무작위형)**도 선택해서 실행할 수 있음
- 두 수요 강도를 기본 비교함
  - **normal(보통)**: 초당 0.12명, 분당 7.2명
  - **congested(혼잡)**: 초당 0.30명, 분당 18명
- 각 조건을 기본 30회 반복하고 같은 반복 안에서는 같은 난수 씨앗을 사용함
- 층고 3.5m, 최고속도 2.5m/s, 가속·감속도 1.0m/s²를 기본값으로 사용함
- 정차 지점 사이의 거리에 따라 짧은 이동은 삼각형 속도 프로파일, 긴 이동은 최고속도 구간이 있는 사다리꼴 속도 프로파일로 계산하고 1초 단위로 올림함
- 정차시간은 `기본 문 개폐 4초 + 탑승 0.8초/명 + 하차 0.6초/명`을 더한 뒤 1초 단위로 올림함
- 일반적인 상·하행 호출 버튼을 가정하며 목적층은 승객이 탄 뒤에만 경로에 반영함
- 한 반복 안에서는 세 배차 방식에 완전히 같은 승객 자료를 사용함
- 패턴 사이에서도 도착 시각은 같게 하고 출발·목적층 구성만 바꿈
- 비교 방식
  - **closest**: 현재 층과 호출층 사이의 거리가 가장 짧은 차량
  - **eta**: 현재 방향, 예정 정차, 이동 시간과 문 시간을 반영한 예상 도착시간이 가장 짧은 차량
  - **priority_eta**: ETA를 기본으로 하되 45초 이상 기다린 호출이 생기면 미처리 호출을 오래된 순서로 재배분
- 출력 지표
  - 평균 대기시간
  - 95백분위 대기시간
  - 60초 초과 대기 비율
  - 정차 시 탑승 거절률: 차량이 실제로 정차했으나 자리가 부족해 한 번이라도 못 탄 승객의 비율. 기존 CSV 열 이름은 `boarding_failure_rate`이며, 만원 차량의 무정차 통과는 포함하지 않음
  - 평균 탑승시간(보조 지표)

모든 엘리베이터는 1층에서 시작한다. 승객이 발생하는 시간 구간이 끝나도 이미 발생한 승객은 모두 목적층에 도착할 때까지 시뮬레이션을 계속한다.

## 실행

Python 3.10 이상에서 다음과 같이 실행한다.

~~~powershell
python elevator_sim.py
~~~

기본 실행은 보통·혼잡 수요, 세 교통 패턴, 세 배차 방식을 각각 30회 비교한다. 결과는 다음 두 파일로 저장된다.

- **output/elevator_experiment_runs.csv**: 각 반복의 원자료와 난수 씨앗·실험 조건
- **output/elevator_experiment_summary.csv**: 조건별 평균, 표준편차, 95백분위 기준 순위

짧은 시험 실행:

~~~powershell
python elevator_sim.py --duration 600 --runs 3 --seed 42
~~~

특정 패턴만 실행하거나 균일 무작위형을 함께 비교할 수도 있다.

~~~powershell
python elevator_sim.py --traffic-patterns up_peak
python elevator_sim.py --traffic-patterns uniform up_peak interfloor down_peak
~~~

출근형·퇴근형에서 주된 방향의 비중은 기본 85%이며 다음처럼 변경할 수 있다.

~~~powershell
python elevator_sim.py --peak-share 0.9
~~~

정차시간 가정도 실행 옵션으로 바꿀 수 있다.

~~~powershell
python elevator_sim.py --base-door-seconds 3 --boarding-seconds-per-passenger 1.0 --alighting-seconds-per-passenger 0.8
~~~

층고·최고속도·가속도 가정도 바꿀 수 있다.

~~~powershell
python elevator_sim.py --floor-height-m 3.5 --max-speed-mps 2.5 --acceleration-mps2 1.0
~~~

이동시간은 층수에 고정 초를 곱하지 않는다. 이동거리 `d`, 최고속도 `v`, 가속도 `a`에 대해 `d <= v²/a`이면 가속 직후 감속하는 삼각형 프로파일을, 그보다 길면 최고속도 구간을 포함한 사다리꼴 프로파일을 사용한다. 따라서 장거리 이동의 층당 평균 시간은 한 층 이동보다 짧다. 여기의 기본 물리값은 실제 대상 건물에서 측정한 값이 아니므로 최종 분석에서는 민감도 분석이나 실측 자료로 보정해야 한다.

ETA 방식은 이미 탑승한 승객의 하차 인원과 배정된 호출의 대기 인원을 이용해 예정 정차시간도 추정한다. 일반 상·하행 호출 방식이므로 아직 탑승하지 않은 승객의 목적층은 ETA 경로에 미리 반영하지 않는다.

수요 강도는 건물 전체의 초당 승객 발생률이다. 기본 강도나 저장 위치는 다음처럼 변경할 수 있다.

~~~powershell
python elevator_sim.py --normal-rate 0.1 --congested-rate 0.25
python elevator_sim.py --output-dir results
~~~

기존처럼 하나의 사용자 지정 강도만 실행할 수도 있다. 이 경우 **custom** 조건 하나만 생성된다.

~~~powershell
python elevator_sim.py --arrival-rate 0.2 --duration 3600 --runs 30
~~~

짧은 기능 확인에서 CSV 파일을 만들지 않으려면 다음 옵션을 쓴다.

~~~powershell
python elevator_sim.py --duration 120 --runs 1 --no-csv
~~~

테스트 실행:

~~~powershell
python -m unittest -v
~~~

~~~

## “더 우수한 방식”의 기본 판정

기본판은 **95백분위 대기시간이 더 짧은 방식을 우선**한다. 평균은 소수의 긴 대기를 가릴 수 있고, 60초 초과 비율은 기준값 하나에 민감한 반면, 95백분위는 대기시간 분포의 꼬리를 연속적인 값으로 비교할 수 있기 때문이다.

코드는 P95 평균이 정확히 같은 경우 정차 시 탑승 거절률, 60초 초과 대기 비율, 평균 대기시간 순으로 비교한다. 실질적 동률을 판정할 수치 허용폭은 아직 없다. 최종 보고서에서는 반복별 불확실성도 함께 제시하고 “P95가 개선되더라도 정차 시 탑승 거절률이 크게 나빠지면 우수하다고 보지 않는다” 같은 기준을 정할 수 있다. 지금 정하는 기준은 결과를 확인한 뒤의 결정이므로 사전 등록한 기준이라고 표현하지 않는다.

## 결과 검토 (2026-11-07)

기본 실험은 6개 조건 × 3개 방식 × 30회로 540행이며, 민감도 분석은 2,610행이다. 기본 실험 원자료의 540행을 민감도 분석에서도 같은 설정과 씨앗으로 재현했으며, 민감도 안에서도 물리값 기본 조건 180행이 수요 분석과 겹친다. 두 파일 전체의 고유 설정·씨앗·방식 조합은 2,430개다. 서로 다른 씨앗을 쓴 반복은 각 조건당 30개이며, 파일의 행 수를 독립 표본 수로 합산하지 않는다.

아래 P95는 **각 반복에서 계산한 승객 대기시간 95백분위의 30회 평균**이다. 모든 반복의 승객을 합친 분포의 P95와는 다르다. 평균 대기시간·비율 역시 반복별 값을 동일 가중치로 평균한다.

| 수요 | 교통 패턴 | closest P95(초) | eta P95(초) | priority_eta P95(초) | priority_eta 평균(초) | 60초 초과 비율 | 정차 시 탑승 거절률 |
|---|---|---:|---:|---:|---:|---:|---:|
| 보통 | 출근형 | 736.98 | 233.51 | 46.96 | 17.99 | 2.44% | 0.85% |
| 보통 | 층간형 | 121.88 | 69.75 | 66.73 | 25.28 | 7.78% | 0.00% |
| 보통 | 퇴근형 | 98.98 | 58.28 | 55.77 | 23.50 | 3.98% | 0.00% |
| 혼잡 | 출근형 | 4365.71 | 4102.38 | 703.67 | 356.33 | 79.15% | 77.71% |
| 혼잡 | 층간형 | 1138.94 | 839.72 | 227.17 | 82.63 | 50.67% | 22.05% |
| 혼잡 | 퇴근형 | 1118.27 | 624.64 | 481.20 | 111.16 | 44.61% | 16.65% |

`priority_eta`는 기본 6개 조건에서 평균·P95가 모두 가장 작다. 따라서 현재 결과가 평균과 긴 대기의 필연적 상충을 보여 준다고 쓰지 않는다. 보통 층간형은 평균이 25초여도 60초 초과 대기가 약 7.8%라서, 평균에 더해 꼬리 지표를 확인할 필요가 있음을 보여 준다.

수요 강도 5수준 × 교통 패턴 3종의 15개 조건 중 `priority_eta`가 14개에서 P95 1위였다. 저수요(초당 0.08명) 퇴근형에서는 `eta`가 43.440초, `priority_eta`가 43.525초로 사실상 비슷했다. 물리값 분석은 `priority_eta`만 실행했으므로, 물리값을 바꿔도 세 방식의 순위가 유지된다는 결론은 아직 내릴 수 없다. 가장 큰 P95 증가 사례는 혼잡 퇴근형에서 최고속도를 2.5에서 2.0m/s로 낮췄을 때의 약 44.6%였다.

### 반복별 불확실성 검토

~~~powershell
python validate_results.py
~~~

`validate_results.py`는 CSV 네 파일의 요약값·순위·반복 짝·중복 실행을 확인하고 `output/research_validation.json`에 결과와 원본 SHA-256을 기록한다. 원자료를 바꾸거나 시뮬레이션을 재실행하지 않는다.

같은 반복의 `priority_eta P95 - eta P95`를 짝지어 10,000회 재표집한 백분위 부트스트랩 구간이다. 음수는 `priority_eta`에 유리하다. 재표집 단위는 승객이 아니라 **반복 실행의 짝**이다.

이 구간은 현재 모형 안에서의 난수 변동을 평가한다. 모형 가정의 오차를 포함하지 않고 다중비교 보정도 하지 않았으므로, 전체 조건에 대한 확증적 검정이나 실제 건물 성능의 신뢰구간으로 해석하지 않는다.

저수요 퇴근형의 같은 차이는 +0.084초이고 탐색적 95% 구간은 [-1.010, +1.053]초다. 따라서 해당 조건에서 `eta`가 확실히 우수하다고 단정하지 않는다.

### 최종 포스터 전에 반영할 해석과 구현 범위

1. **배차 기능의 기여 구분**: `eta`에는 주기적 재배분이 없고 `priority_eta`에만 있다. 현재 비교는 오래된 호출을 앞세워 재배분하는 전체 규칙의 비교다. 우선순위만의 효과를 분리하려면 같은 주기의 재배분만 수행하는 대조 방식이 추가로 필요하다. 호출 정렬이 곧 승객 탑승 순서 보장을 뜻하지도 않는다.
2. **탑승 거절의 측정 범위**: 정원이 1명인 차량에 1층→3층 승객과 2층→3층 승객을 동시에 발생시키면, 2층 승객은 만원 차량이 3층에 갔다 돌아오는 동안 20초를 기다리지만 `failed_boardings`는 0이다. 진단 코드가 이 사례를 기록한다. 기존 비율은 정차 시 거절률로 명시해야 하며, 용량 때문에 생긴 지연 전체로 해석하지 않는다.
3. **호출 방향·이동 중 상태의 단순화**: 정차 시 상·하행 호출을 차량의 현재 방향으로 걸러 탑승시키지 않으며, 출발 후에는 다음 목표층까지 구간을 확정한다. 이동 중 `current_floor`는 마지막 출발층이라 `closest`의 거리도 이 이산 상태를 기준으로 한다. 실제 일반 호출 운행의 상세 재현으로 주장하지 않는다.
4. **호출 정보의 단순화**: ETA 정차시간 추정에 실제 대기 인원 수를 사용한다. 일반 상·하행 버튼만으로 그 인원을 정확히 관측한다는 근거는 없으므로, 완전한 대기 인원 정보를 가정한 모형이라고 설명한다.
5. **혼잡의 의미**: 높은 수요에서 긴 대기가 급증했다는 결과는 제시할 수 있다. 현재는 평형 처리능력·임계 도착률·지속 과부하를 따로 추정하지 않아, 특정 도착률이 실제 건물 처리능력을 넘었다고 단정하지 않는다.

포스터에서 사용할 수 있는 현재 결론은 다음과 같다.

> 가정한 25층·3대 모형에서 오래된 호출을 앞세워 ETA로 재배분하는 규칙은 기본 6개 조건의 평균 대기와 반복별 P95를 함께 줄였다. 다만 높은 수요에서는 이 규칙에서도 긴 대기가 남았다. 따라서 평균과 꼬리 대기를 함께 보고해야 하며, 효과의 크기와 탑승 거절률은 배차·용량 측정 정의 및 모형 가정과 함께 해석해야 한다.

## 재배분과 호출 나이 효과를 분리한 실험

기존 예비실험은 `eta`에 없던 재배분 기능과 호출 나이 순서를 `priority_eta`에 동시에 더했다. 두 기능을 분리하기 위해 다음 세 방식을 같은 승객 자료로 비교한다.

| 새 실험 방식 | 차량 선택 | 재배분 | 재배분 시 호출 검토 순서 |
|---|---|---|---|
| `eta` | 간이 ETA 최소 | 없음 | 해당 없음 |
| `redispatch_eta` | 같은 ETA 최소 | 45초부터 매 5초 | 호출 나이와 무관한 무작위 순서 |
| `age_order_eta` | 같은 ETA 최소 | 45초부터 매 5초 | 현재 남아 있는 승객 중 가장 이른 도착 시각 순 |

두 재배분 방식은 동일한 고정 시계와 “모든 대기 호출 재검토” 규칙을 사용한다. 이미 출발한 차량의 목표층과 탑승한 승객의 목적층은 유지한다. 실제 재배분 횟수는 호출 유무와 종료 시각에 따라 달라질 수 있지만, 호출 나이가 재배분 실행 시점을 바꾸지는 않는다. 이 설계의 `age_order_eta`는 45초 이상 된 호출이 있어야 작동했던 이전 `priority_eta`와 다르다. 이전 결과와 이름을 섞어 사용하지 않는다.

무작위 순서의 특정 실현 하나를 선택하는 일을 피하기 위해 같은 승객 발생 씨앗마다 5개 순서 씨앗을 사용한다. 대조 방식의 반복별 P95·평균 등은 이 5회의 값을 먼저 평균한다. 그 뒤 독립적인 승객 발생 씨앗 30개를 분석하므로 **표본 수는 조건당 30개**다. 총 계산량은 6개 조건 × 30개 씨앗 × (ETA 1회 + 나이 순서 1회 + 무작위 순서 5회) = 1,260회다. 45초·5초는 기존 모형과 연결하기 위한 연구 설정이며 이번에 최적화한 값이 아니다.

~~~powershell
python ablation_experiment.py
~~~

결과는 `output/ablation/`에 저장된다.

- `protocol.json`: 결과 산출 전 저장하는 실험 규칙·씨앗·소스 해시. 외부 사전등록을 뜻하지 않음
- `results.json`: 개별 실행, 순서 반복을 평균한 실행, 조건별 요약, 세 가지 효과의 짝지은 부트스트랩 구간, 층별 요약
- `passengers.jsonl.gz`: 승객별 도착·탑승·하차·정차 시 거절 횟수와 비교 집단 표시를 담은 압축 JSON Lines

주요 대비는 `age_order_eta - redispatch_eta`의 P95 차이다. 보조 대비로 `redispatch_eta - eta`와 `age_order_eta - eta`를 계산한다. 음수는 앞 방식에 유리하다. 각각의 P95는 승객 발생 반복별 P95를 평균한 값이며 전체 승객을 합친 P95가 아니다. 신뢰구간은 30개 승객 발생 씨앗의 짝을 10,000회 재표집한 탐색적 95% 백분위 구간이다. 여러 교통 조건의 비교에 대한 다중비교 보정은 하지 않았다.

수혜 승객은 전체 대기시간과 함께 다음 관점으로 살핀다.

- **고정된 긴 대기 집단**: ETA에서 가장 오래 기다린 `ceil(승객 수 × 5%)`명의 ID를 정해 다른 방식에서도 동일인을 추적한다. ETA 결과를 보고 선택한 집단이므로 그 집단의 개선은 기술적 분석으로 해석한다.
- **층별 결과**: 출발층별 평균·P95·60초 초과 비율·정차 시 거절률과 승객 수를 함께 남긴다. 층별 요약은 승객이 실제로 발생한 반복의 값을 동일 가중치로 평균한다. 희소한 층의 P95는 표본 수와 함께 해석해야 한다.
- **반복 거절**: 실제 정차했지만 두 번 이상 못 탄 승객의 비율을 계산한다. 만원 차량의 무정차 통과는 기존 거절 정의에 포함하지 않는다.

실험과 통계 분석은 표준 라이브러리만 사용한다. 그림 생성에만 `matplotlib`이 필요하다.

~~~

나이와 무관한 순서로 재배분해도 ETA 대비 P95가 6개 조건 모두 낮았고, 해당 차이의 탐색적 구간은 모두 음수였다. 여기에 오래된 호출 순서를 더한 P95 개선은 5개 조건에서 불확실했으며, 혼잡 퇴근형에서는 오히려 늘었다. 구간에 0이 포함된다는 사실은 두 방식의 효과가 같다는 증명이 아니다. 이 결과는 **새 고정 시계 실험의 대비**이며 이전 `priority_eta` 결과를 그대로 분해한 인과 추정은 아니다.

혼잡 퇴근형의 평균 대기시간도 무작위 순서 107.68초에서 나이 순서 115.05초로 증가했다. 짝지은 차이는 +7.37초, 탐색적 95% 구간은 [+4.21, +10.55]초였다. 동시에 나이 순서 적용 시 대기가 줄어든 승객은 반복별 평균 약 51.84%, 늘어난 승객은 약 44.63%였다. 이는 **승객별 나이 순서 대기시간과 같은 승객의 무작위 순서 5회 평균**을 비교한 기술 통계다. 다수의 소폭 개선과 소수의 큰 악화가 함께 나타날 수 있으므로 수혜 인원 비율만으로 전체 개선을 판단하지 않는다.

기본 ETA에서 긴 대기를 경험했던 상위 5%의 같은 승객을 추적하면, 재배분 두 방식 모두 ETA보다 평균 대기가 줄었다. 그러나 나이 순서가 무작위 순서보다 이 집단을 일관되게 더 잘 보호하지는 않았다. 혼잡 퇴근형의 해당 집단 차이는 +37.38초였지만 구간은 [-13.19, +81.98]초로 불확실했다.
